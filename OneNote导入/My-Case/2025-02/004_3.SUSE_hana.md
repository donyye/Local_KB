当出现问题时，node的动作是 Powering Off 而不是 reboot，这个是与 cluster 设置有关系。

    stonith-action=off

 

另两个cluster的通信使用的udp模式，在交换机比较繁忙和不稳定的情况下可能会导致堵塞或异常，使cluster同步受阻，建议把 udp 改成功TCP设置。

# /etc/corosync/corosync.conf

totem {

        cluster_name:    mis4pdb

        crypto_hash:    none

        rrp_mode:       passive

        join:   60

        max_messages:   20

        vsftype:        none

        secauth:        off

        crypto_cipher:  none

        cluster_name:   s4pcluster

        token:  5000

        token_retransmits_before_loss_const:    10

        clear_node_high_bit:    yes

        version:        2

        interface 

        interface 

        consensus:      6000

        transport:[      udp]

        ip_version:     ipv4

......

 

修改成 TCP 的方法，在 yast 这种里，将传输从 Multicast更改为 Unicast：

<https://documentation.suse.com/sle-ha/15-SP6/html/SLE-HA-all/cha-ha-ycluster.html#sec-ha-installation-setup-channels>

 

改完后后续可以继续观察看是否有相同问题。
