关于这个错误在 Redhat 官网有相似的错误，问题发生在RHEL9.4这个版本上， 记录的是某些驱动诱发的这个问题，KB给出的方式通过升级系统版本到9.6来解决这个问题。

 

<https://access.redhat.com/solutions/7130809>

 

Segmentation fault caused by BXI driver handling of MMU notifiers during recessive page-fault resolution

 Solution Verified - Updated September 26 2025

 

Environment

- Red Hat Enterprise Linux 9.4
- NVidia GraceHopper superchips.
- BXI interconnect network.

Issue

- Application failures due to segmentation faults.
- Issue occurs under high memory load; comes from recessive page-fault resolution attempts by BXI NIC driver.
- Expected behavior of MMU notifier for range-based invalidations was not met. Messages like below were observed at the time of the issue:

Resolution

- For RHEL 9.4.z: The issue is fixed in kernel-5.14.0-427.74.1.el9_4.x86_64 via errata [RHSA-2025:9584](https://access.redhat.com/errata/RHSA-2025:9584).

 

$ rpm --changelog -qp kernel-5.14.0-427.74.1.el9_4.x86_64.rpm | grep RHEL-93742

- Fix mmu notifiers for range-based invalidates (Marc Milgram) [RHEL-93742]

- For RHEL 9.6.z: The issue is fixed in fixed in kernel-5.14.0-570.26.1.el9_6.x86_64 via errata [RHSA-2025:10837](https://access.redhat.com/errata/RHSA-2025:10837).

 

$ rpm --changelog -qp kernel-5.14.0-570.26.1.el9_6.x86_64.rpm | grep RHEL-93743

- Fix mmu notifiers for range-based invalidates (Jay Shin) [RHEL-93743]

- For RHEL 9.7: Issue is currently under investigation in a private Jira RHEL-83459.

Root Cause

- The MMU notifier occasionally issued invalidations with start = end ranges, which is unexpected.
- These invalidation requests triggered segfaults during page-fault handling in the bxi driver.
- The issue was fixed upstream via commit: f7edb07ad7

 

 

 

总的来看这个问题更多偏向于kernel bug问题，另外 Rocky 9.4已经是停止支持了，如果需要升级建议是升级到 Rocky 9.7。

 

如果需要进一步排除硬件问题建议跑 memtest86+ 对内存做进一步的检查。

 

 

我也把此问题向 Rocky 社区提交了一个bug，得到回复也是建议升级到 Rocky9.7，9.4 已经 EOL，他们也不会在这个版本上做分析。
