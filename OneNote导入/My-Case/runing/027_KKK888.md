常用命令：

》自动补全：

source \<(kubectl completion bash)

# 在 bash 中设置当前 shell 的自动补全，要先安装 bash-completion 包，一般默认会有安装。

echo "source \<(kubectl completion bash)" \>\> ~/.bashrc # 在你的 bash shell 中永久地添加自动补全

 

》环境变量

# export KUBECONFIG=/etc/kubernetes.admin.conf

如果没环境变量，默认会去这个地方找config配置文件来读取node信息

# cat ~/.kube/config

 

# kubectl config view # 显示合并的 kubeconfig 配置

 

》切换集群

# kubectl config use-contest xxxx

 

 

》kubectl apply[   ]重新配置一次，需要有 yaml 文件

kubectl apply -f ./my-manifest.yaml

kubectl apply -f ./my1.yaml -f ./my2.yaml[  #]通过两个文件创建

 

》kubectl create 创建，如果已经有会报错

# kubectl create deployment nginx --image=nginx

--\> deployment 是创建的资源，它的名称是 nginx, 后面是使用的镜像，后面加 -n 可以部署到不同的 namespace。

--\> 查看你刚刚建的 kubectl get deploy nginx -oyaml

 

》通过创建方式，实际不创建，导出yaml文件

kubectl create deployment nginx2 --image=nginx --dry-run=client -oyaml \> nginx2-dp.yaml

 

》查看 deply

kubectl get deploy

 

》删除deply

kubectl delete deploy nginx

--\>通过yaml文件来删除，需要注意的是如果文件里有自定命名空间，那在删除的时候后面不用加 -n 来指定，否则就需要。

kubectl delete -f user.yaml

 

》查看POD

kubectl get po -n kubernetes-dashboard

-- 删除POD

kubectl delete po dashboard-metrics-xxxxxxxxxxx -n kubernetes-dashboard

--\> pod 是有命名空间隔离的，所以要用"-n"指定命名空间

 

》查看 server

kubectl get svc

kubectl get svc -A

 

》输出所有命名空间的IP地址

kubectl get po -A -owide

-- node ip 地址

kubectl get node -owide

 

kubectl get clusterrole

 

》具有命名空间隔离的资源

kubectl api-resources --namespaced=true

--\> 没有隔离性的资源

kubectl api-resources --namespaced=false 

 

》查看资源并排序

kubectl get services --sort-by=.metadata.name

--\> 指定命名空间并用名称排序

kubectl get services -n kube-system --sort-by=.metadata.name

--\> 列出 Pod，按重启次数排序

kubectl get pods [ -n kube-system] --sort-by=['.status.containerStatuses[0].restartCount']

--\> 取值的方法

Kubectl get po etcd-k8s-master01 -n kube-system -oyaml

》查看创建pod时的标签

kubectl get po -n kube-system --showl-labels

kubectl get po -n kube-system -l k8s-app=calico-node

 

》资源更新

kubectl create deployment nginx --image=nginx[  --\> ]创建

Kubectl set image deploy nginx nginx-nginx:v2[  --\> ]更新

-----

kubectl rollout history deployment/frontend[                      # ]检查 Deployment 的历史记录，包括版本

kubectl rollout undo deployment/frontend[                         # ]回滚到上次部署版本

kubectl rollout undo deployment/frontend --to-revision=2[         # ]回滚到特定部署版本

kubectl rollout status -w deployment/frontend[                    # ]监视 "frontend" Deployment 的滚动升级状态直到完成

kubectl rollout restart deployment/frontend[                      # ]轮替重启 "frontend" Deployment

cat pod.json | kubectl replace -f -[                              # ]通过传入到标准输入的 JSON 来替换 Pod

 

 

》查看命名空间里pod log

Kubectl get po

kubectl logs -f calico-node-2w9vh -n kube-system

 

》查看在容器上可以使用什么命令

kubectl exec nginx-67xxxxxx-pnqhs -- ls

--\> 使用 bash 进入容器并

kubectl exec -ti nginx-67xxxxxx-pnqhs -- bash

 

》性能查看

kubectl top node

kubectl top po -A

kubectl top po -n \<命名空间名字\>
