按照建议，您将从主机中删除kvm服务器、kvm工具、xen服务器和xen工具包，并尝试仅安装kvm服务器和kvm工具包。

请检查以下步骤，

对Hana系统数据库和租户数据库进行完整备份，并将其移动到远程位置。

对VM磁盘进行完整备份。VM磁盘的位置如下所述。将此备份复制到更安全的位置。

 

/var/lib/libvirt/images/sles15sp2-disk1.qcow2

 

3.转储VM配置，将此文件移动到更安全的位置，

 

# virsh dumpxml sles15sp2\> /opt/sles15sp2.xml

 

4.删除kvm服务器、kvm工具、xen服务器和xen工具模式

# zypper rm -t pattern kvm_server

# zypper rm -t pattern kvm_tools

# zypper rm -t pattern xen_server

# zypper rm -t pattern xen_tools

     

5.安装kvm服务器和kvm工具模式

# zypper install -t pattern kvm_server

# zypper install -t pattern kvm_tools

 

6.安装KVM软件包后，libvirtd服务能够正常启动，您可以将VM磁盘复制到其原始位置并启动VM，

# virsh define /opt/sles15sp2.xml

所以现在我假设无法开机的VM能够开机并正常工作。

请进行完整的VM和KVM主机备份，并按照客户之前遵循的相同流程进行操作，即SLES 15 SP2==\>SLES 15 SP4==\>SLES 15 SP5，但首先升级KVM主机，然后升级VM。

此外，在客户从SLES 15 SP2升级到SLES 15 SP4后，请确保进行完整的KVM主机和VM备份，以便在升级到SLES15 SP后出现任何问题时，它将帮助客户恢复到SLES15 SP4。

我担心以下问题，

•我担心这是否是一个理想的设置，因为物理主机既是HANA DB又是KVM主机。通常，HANA DB主机不应运行其他工作负载。请与客户一起根据SAP和SUSE的最佳实践指南评估此设置。

•此服务器上的根分区不使用BTRFS文件系统，这意味着客户无法利用snapper的内置优势。Snapper在修补和升级场景中至关重要，因为它提供了在出现问题时恢复到以前状态的选项，从而大大减少了停机时间。

•这似乎是一个标准的SUSE Linux Enterprise Server，而不是SUSE Linux企业版SAP服务器。Hana DB应按照建议在SLES for SAP服务器上运行。

•EXT3被用作Hana DB文件系统。通常，为了提高Hana DB的性能，SAP和SUSE建议使用XFS文件系统。

请与客户核实这些问题，并相应地计划升级。
