案例3:[  ]lck锁与文件系统修复 

2023年12月13日

9:37

ESXI 8\
一次异常重启后本地磁盘上的vm变成无效的状态

 

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_001.png]]

 

登录到ESXI进入到 VM 查看有 \*.lok 文件，说明有锁文件

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_002.png]]

 

 

开始修复：

1. 先把无效的vm都取消注册

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_003.png]]

 

2. 卸载数据存储 

1)[  ]使用 lsof \|grep -I datastore1 检查一下是否有其它东西占用这个存储

2)[  ]卸载 。只是卸载对数据不会有影响，它不是删除。

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_004.png]]

 

 

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_005.png]]

 

voma -m vmfs -f check -d /vmfs/devices/disks/vml.xxxxxxxxxxxxxx -s /tmp/voma-checking.txt

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_006.png]]

 

这里说明一下，为什么选择是 vm1.02xxxxx48:8。

这里看到vmfs 8.61T 这个是数据分区。

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_007.png]]

 

运行完后到 /tem/checking.txt 查看，发现有 331 个错误，算是比较多的，修复的结果有可能成功或是失败，不确定。

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_008.png]]

修复是对块做恢复，但是有些数据本身就坏了，也修复不回来。

 

开始修复

这里有个小插曲，在 8.0 后普通修复没有了，改为了 advfix 。

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_009.png]]

 

voma -m vmfs -f advfix -d /vmfs/devices/disks/vml.xxxxxxxxxxxxxx -p /tmp

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_010.png]]

 

修复完成后结果，修复了333个，看起来还不错。

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_011.png]]

 

修复完后可以再做一次检查，看起来还是有一个错误。但是不一定会有影响

voma -m vmfs -f check -d /vmfs/devices/disks/vml.xxxxxxxxxxxxxx -s /tmp/voma-checking2.txt

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_012.png]]

 

重新挂载存储

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_013.png]]

 

到vm目录里删除\*.lck文件。修复完成后正确情况下是可以被删除的。

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_014.png]]

 

删除 \*.lck文件后重新注册vm

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_015.png]]

 

然后开启vm，是可以正常进入系统。

![[VMware-排错_ESXI_排查_013_案例3_  lck锁与文件系统修复_016.png]]

 

完成

 

已使用 OneNote 创建。
