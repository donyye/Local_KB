总结：

 

12月16日ESXi Host "ptaiser02"上的VM在23:50后被转移到其他Host是因为该5个NAS卷在该主机访问不到，并非ESXi本身的异常情况。

 

12月16日 23:43此时该主机上的状态为：

vmnic5和7没有physical link state down，

                从主机log看到NFS  5个卷分布在两个NFS 端点设备上，即为10.1.76.126和10.1.76.127，23:50故障发生时，NFS client访问不到该两个端点，sun RPC (NFS protocol) session连接不到10.1.76.126和10.1.76.127，所以I/O无法回写。

 

12月16日 16:04 此时vmnic5 physical link state down,  vmnic5的负载将会failover到vmnic7，我们怀疑这个failover过程促进了NFS access访问的恢复，反过来推测，在23:43分的时候vmnic5所在的link上是有异常的，虽然physical link没有down。

 

Vmnic5 down的Failed criteria code是128, 该故障并非来自于ESXi本身，以下是相关信息供参考：

 

Note: Failed Criteria 128 is driver reporting link state down. This can be caused by unplugging the network cable or administratively downing the physical switchport. If this was not an intended link outage it will likely be an issue with the driver, firmware, SFP+ module, cable, and/or switchport of the physical switch. Check the driver by following the below KB, and call the host hardware vendor for further troubleshooting when Failed criteria 128\'s are seen in the vobd log. For more information, see [Determining Network/Storage firmware and driver version in ESXi](https://kb.vmware.com/s/article/1027206).

                Link:  <https://kb.vmware.com/s/article/2014553>

2023-12-16T16:04:00.850Z cpu2:2098157)bnxtnet: bnxtnet_display_link:2916: \[vmnic5: 0x45210aa06000\] NIC Link is down

 \# AutoGrEEEn 说明有EEE功能。EEE是网卡的节能模式。

 

 

技术建议：

1.  检查57416 网路卡的LLDP Agent是否已关闭并确保已关闭，已知该功能会引入一些奇怪的网络现象.
2.  检查57416 网路卡是否可以关闭EEE功能，将其关闭.
3.  请参"总结"部分中的关于"Failed criteria code:128" 的解释，对相关资源做检查和分析，考虑是否存在其他方式方法能够排查网络的异常来源。
4.  当前NFS protocol version是V3，V3版本仅支持single NFS session，不支持session 中继。 所以失去该session即为失去所有path，即为All path down.  我们看到NFS存在两个对端 10.1.76.126和10.1.76.127， 如果这是NFS Server的两个控制器，建议检查该NFS Server 是否支持NFS V4.1， 如果支持，请参考该NFS 厂商的VMware best practice guide，调整拓扑和挂载模式到NFS V4.1。 如果该NFS厂商没有for VMware best practice guide,  可参考该文档： [https://core.vmware.com/resource/nfs-iscsi-multipathing-vsphere#sec10639-sub2](https://core.vmware.com/resource/nfs-iscsi-multipathing-vsphere#sec10639-sub2)
5.  如果该问题复现，请在NFS datastore无法访问的故障现象保持存在的情况下，立刻通过putty登录受影响的ESXi主机，通过以下命令测试是否能够访问到对端的NFS server以及登录对端的NFS service port，从而确认是否存在类似于本次的vmnic5上的异常状态。
    a.  测试是否ping通:  
        1.  vmkping -I vmk2 10.7.76.126  
        2.  vmkping -I vmk2  10.7.76.127
    b.  测试是否能够登录NFS service port：(Note:  NFSd RPC 默认端口为2049，但是会因厂家的配置有所更改，请向NFS厂商咨询 nfsd的具体端口ID )
        1.  nc -z  10.7.76.126  2049
        2.  nc -z  10.7.76.127  2049
        3.  输出以下信息即为端口登录成功：[Connection to 10.1.10.100 2049 port \[tcp/http\] succeeded!]
