IC: 168978346 \
因机房停电导致VC重启后有报文件系统错误，然后进入维护模式

![[VMware-排错_vCenter_排查_013_案例3：VC修复案例_001.png]]

 

先对VC做个快照

通过fsck 对错误提示的路径进行修复后可用正常进入系统

mount -n -o remount,rw /

fsck /dev/mapper/log_vg-log

<https://kb.vmware.com/s/article/2081464?lang=zh_CN>

 

然后发现 storage 日志目录满了，进行清除

<https://kb.vmware.com/s/article/83070>

 

重启VC还是发现无法启动

![[VMware-排错_vCenter_排查_013_案例3：VC修复案例_002.png]]

 

继续检查：\
看到的主机名字与Pnid不一样

"\# /usr/lib/vmware-vmafd/bin/vmafd-cli get-pnid \--server-name localhost"与 "\# hostnamectl status" 不一样。

hostnamectl status 看到的是FQDN，而 Pnid 看到的是 IP 地址。

说明部署时用的IP，而后来主机名字改成了 FQDN，这个时候就需要把 Pnid改成FQDN。\
先确保 DNS 的对FQDN正向和反向解析都可用\
通过5480端口登录修改，在\"网络\"选项右上角选择\"编辑\"。(这个操作可用查看案例1)

![[VMware-排错_vCenter_排查_013_案例3：VC修复案例_003.png]]

 

![[VMware-排错_vCenter_排查_013_案例3：VC修复案例_004.png]]

然后下一步到成功。

 

成功完成后可用尝试重启VC服务，如果起不来需要更新一下STS证书，虽然它可能没过期，但是因为修改过主机名字。

[https://kb.vmware.com/s/article/79248?lang=en_us](https://kb.vmware.com/s/article/79248?lang=en_us) 下载 checksts 

[https://kb.vmware.com/s/article/76719](https://kb.vmware.com/s/article/76719)[   ]下载 fixsts 

 

更新完成后再次重启VC服务器，发现成功启动。

 

为了确保安全，使用 lsdoctor 工具检查，打开KB下载 lsdoctor工具。

<https://kb.vmware.com/s/article/80469?lang=en_us>

python ./lsdoctor.py  \--lscheck

![[VMware-排错_vCenter_排查_013_案例3：VC修复案例_005.png]]

检查显示 No issue 说明没问题。
