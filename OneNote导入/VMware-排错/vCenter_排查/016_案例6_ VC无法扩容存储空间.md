案例6: VC无法扩容存储空间

2024年4月22日

15:16

问题： 

客户有两个node 加一个 VC。

一天发现挂载到这两个 node 的 lun 空间不够了，就在原来的基础上加了1T空间，但是通过VC来查看这个lun无法看到这个空间。

客户在 ESXI web UI里能看到增加的空间，也做了扩展，但是奇怪的是扩展完成后，有一个node会自动缩小回原来的大小。

如图，VC上是看不到增加的空间。

![[VMware-排错_vCenter_排查_016_案例6_ VC无法扩容存储空间_001.png]]

 

先说结论：

此问题是因为 storage share 出来的lun ID不一样导致VC认为这是两个不同lun，所以在VC上看不到，也会导致不同步的问题。

这是其中一个node,可以看到红款那里，lun 是0。

![[VMware-排错_vCenter_排查_016_案例6_ VC无法扩容存储空间_002.png]]

 

另外一个node, 可以看到 lun 是 1。所以这两个ID 不一样。但是是需要一样的。

![[VMware-排错_vCenter_排查_016_案例6_ VC无法扩容存储空间_003.png]]

 

检查storage那端配置可以看到， host lun ID 分给两个 node ，一个是 0 一个是1，原因就在这里

![[VMware-排错_vCenter_排查_016_案例6_ VC无法扩容存储空间_004.png]]

尝试过手动配置是不会这样的，可能是有人手动改过。

 

解决的方法有两种。

1）把这个lun上的VM都迁移到其它lun上，然后umount lun，并在存储这边改 lun ID 为一样。

但是需要注意的是，如果VM不能迁移，那VM只能关机，并全部注销，否则 lun 无法 umount，需要mount回来后再手动注册VM。

2）就是重新建一个lun，确保ID一样，然后挂给ESXI，然后再迁移VM到新lun。

 

==================

另外也发生过其它问题导致，比如直接在ESXI上的扩容，一开始就没在VC上做，也会有出现不同步的问题。

这个时候最要注意的是：

在存储扩容后要到ESXi上去做个adapter rescan，在VC那边rescan也行，如果lun是给多个主机的，那一定要仔细检查每个主机都看到了LUN扩容后的大小才可以进行下一步。
