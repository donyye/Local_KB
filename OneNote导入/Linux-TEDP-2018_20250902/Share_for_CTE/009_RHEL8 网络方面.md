网卡名字的命名，默认情况下，Red Hat Enterprise Linux 根据 /usr/lib/systemd/network/99-default.link 文件中的 NamePolicy 设置选择设备名称。

NamePolicy 中值的顺序非常重要。Red Hat Enterprise Linux 使用在该文件中指定的以及 udev 生成的第一个设备名称。

\# vim /usr/lib/systemd/network/99-default.link

\[Link\]

NamePolicy=kernel database onboard slot path

MACAddressPolicy=persistent

 

从这个默认的来看，它首先是以kernel的规则来命名网卡名字。

如果内核 已经为此网卡设置了固定的可预测名称， 那么不进行任何重命名操作。

如果您手动配置 udev 规则以更改内核设备名称，则优先使用这些规则。

 

 

kernel - 如果内核 已经为此网卡设置了固定的可预测名称， 那么不进行任何重命名操作。

database - 基于网卡的 ID_NET_NAME_FROM_DATABASE 属性值(来自于udev硬件数据库)设置网卡的名称。

onboard - 基于网卡的 ID_NET_NAME_ONBOARD 属性值(来自于板载网卡固件)设置网卡的名称。

slot - 基于网卡的 ID_NET_NAME_SLOT 属性值(来自于可插拔网卡固件)设置网卡的名称

path - 基于网卡的 ID_NET_NAME_PATH 属性值(来自于网卡的总线位置)设置网卡的名称。

 

 

而UDEV里的命名规则

ll /usr/lib/udev/rules.d/\*-net.\*

 

1)/usr/lib/udev/rules.d/60-net.rules 文件中的规则会让 udev 帮助工具 /lib/udev/rename_device 查看所有 /etc/sysconfig/network-scripts/ifcfg-xxxx 文件。如果发现包含 HWADDR 条目的 ifcfg 文件与某个接口的 MAC 地址匹配，它会将该接口重命名为 ifcfg 文件中由 DEVICE 指令给出的名称。

 

2)/usr/lib/udev/rules.d/71-biosdevname.rules 中的规则让 biosdevname 根据其命名策略重命名该接口，即在上一步中没有重命名该接口、已安装 biosdevname、且在 boot 命令行中将 biosdevname=0 作为内核命令给出。

 

\# 如果这项有参数了，和现有参数用空格分开 GRUB_CMDLINE_LINUX=\"net.ifnames=0 biosdevname=0\"
