512e drives are not supported with the current versions of vSphere and VSAN due to potential performance issues when using these drives.

不支持是因为潜在的性能问题。并且这个潜在是很容易发生，并且性能影响非常大。

其实这几个系统是可以用512e的，因为logical sector还是512bytes，只是它们无法感知512e，做不到自动对齐。

 

就像KB提到的，当IO未对齐或者不是4KB的倍数时，就会产生惩罚，文件系统未优化，会影响性能：

 

![[Technology_ALL_VMware_分析案例_021_关于硬盘为4KN_002.png]]

 

可以看下这张图，Misaligned情况下 block 0落在了两个physical sector0和1上，这样的block0叫做misaligned data，既影响空间又影响IO 。

 

On misaligned data, the 512e HDD must perform READ-MODIFY-WRITE functions to complete the write operations. Therefore, 512e HDD suffers significant performance loss (50%) in the random writes, misaligned data operations.

 

解释一下READ-MODIFY-WRITE，还是以下图的Misaligned情况为例，当block0写在了硬盘的sector0的后4个logical sector和sector1的前4个logical sector后，再想写入block1，硬盘要先把sector1的前4个logical sector读出来，把它们和block1的前4个logical sector合并成一个完整的4KB sector（8x512bytes）后，再写入sector1，因为硬盘一次只能写一个完整的physical sector，而无法只写physical sector中的一部分logical sector 。

 

当然如果幸运，写请求和Aligned指向的情况相同的就不会有此问题了，在兼容列表里面的OS支持自动对齐也不会有此问题。

 

![[Technology_ALL_VMware_分析案例_021_关于硬盘为4KN_003.png]]

 

影响不止这些，官方FAQ还提到了应用功能性影响和数据丢失风险（在突然断电又无有效cache保护时）。
