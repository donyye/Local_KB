  在vSAN monitor界面中检查VSAN总容量和状态有无异常和报错，若有则停止并联系我们检查

  将待升级驱动主机上的虚拟机无论开机或者关机都vmotion迁移到其他主机

  将主机置于维护模式，维护模式窗口中跳出的选项选择"保持数据可访问性" 

                 

  ![[Technology_ALL_VMware_分析案例_083_驱动升级_001.png]]

   

  确认主机进入维护模式后，将附件驱动上传至ESXi 的tmp目录下， 执行命令安装, 请注意检查安装的结果是成功还是失败，若是失败则立即停止联系我们查找原因。

                  esxcli software vib install -v  /tmp/lsi-mr3.xxxxxxxx.vib     请注意包的名称和路径一定要输入正确

                 

  以上命令安装成功后，请将该主机执行正常重启，

  主机重启完成后，检查主机状态是否正常， 然后退出维护模式，在vSAN monitor界面中，检查VSAN的每一项健康状态，以及VSAN的总容量是否正常， 若有异常则停止并联系我们检查。

  移动若干不重要的VM至该主机，等待20至30分钟左右观察是否有异常，若一切正常，则继续下一台主机的维护过程。

  Hi Mark,

  如我们电话所谈,  目前VSAN健康状态正常. 

  那几个黄色报警做相应安排即可消除,  另外我们提到的VSAN手动更新HCL 以及会触发resync的情景如下, 请参考.

  [https://kb.vmware.com/s/article/2145116](https://kb.vmware.com/s/article/2145116)

   

  会触发resync的情景如下

  1.  Editing a virtual machine (VM) storage policy. When you change VM storage policy settings, vSAN might initiate object recreation and subsequent resynchronization of the objects. 
      a.  Certain policy changes might cause vSAN to create another version of an object and synchronize it with the previous version. When the synchronization is complete, the original object is discarded. 
      b.  vSAN ensures that VMs continue to run, and resynchronization does not interrupt their operation. This process might require additional temporary capacity. 
  2.  Restarting a host after a failure. 
  3.  Recovering hosts from a permanent or long-term failure. If a host is unavailable for more than 60 minutes (by default), vSAN creates copies of data to recover the full policy compliance. 
  4.  Evacuating data by using the Full data migration mode before you place a host in maintenance mode. 
  5.  Exceeding the capacity threshold of a capacity device. Resynchronization is triggered when a capacity device in the vSAN cluster approaches or exceeds the threshold level of 80 percent.
