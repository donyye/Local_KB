【客户环境】

R940XA服务器使用Intel X710网卡，光纤口A和B分别连接两台光纤交换机，两台光纤交换机再连接一台核心交换机。（交换机非DELL）

 

【问题现象】

R940XA服务器安装Redhat 7.4，双光口绑定。在操作系统中运行命令ifdown eth4（A路），华三交换机接口物理链路（link）和网络协议状态（protocol）均UP，导致A网卡的mac地址同时出现在A、B路交换机上。

2、R940XA服务器双光口绑定，常ping IP后物理插拔A光纤线，客户反馈频繁出现丢包现象。

 

【解决方法】

Redhat 7.x版本实验室实测ifdown操作后，A路网卡链路没有断干净，导致A路网卡仍在往华三交换机发mac报文。Redhat 6.x版本可以通过命令ifdown断网卡。

2、Rerdhat网卡配置文件调整disable-fw-lldp为on解决。

Intel X710系列NIC（i40e）不接收LLDP帧

SOLUTION - 已更新 May 16 2018 at 5:20 PM - 

[中文 (中国) (Machine Translation) ](https://access.redhat.com/mt/zh-hans/solutions/3446721)

 这里的内容是由机器翻译的，可能会包括一些错误。 [请提供对翻译的反馈意见](https://access.redhat.com/mt/zh-hans/solutions/3446721#)

环境

- 红帽企业Linux 7
- Intel 700系列NIC硬件

问题

- 在运行时lldpd服务和使用lldptool ，使用tcpdump进行数据包捕获表明从交换机接收的数据永远不会有任何LLDPDU帧。

解析度

- 这是预期的行为。有关说明，请参阅本文的根本原因部分。
- 如有必要，请使用以下命令禁用固件LLDP代理，将正确的PCI总线地址插入路径。 请注意，这可能导致PF自行重置！ ：\
  [Raw](https://access.redhat.com/mt/zh-hans/solutions/3446721#)\
  \# echo lldp stop \> /sys/kernel/debug/i40e/\<pci bus address\>/command

根本原因

- 英特尔700系列网卡在固件中运行LLDP代理，用于处理和"吸收"从交换机接收的任何LLDPDU帧。因此，操作系统永远不会看到这些帧。
- 供参考： [适用于英特尔（R）以太网控制器700系列的i40e Linux \*基础驱动程序](https://downloadmirror.intel.com/27403/eng/readme.txt)\
  [Raw](https://access.redhat.com/mt/zh-hans/solutions/3446721#)\
  Data Center Bridging (DCB)\
  \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\--\
  \
  NOTE:\
  The kernel assumes that TC0 is available, and will disable Priority Flow\
  Control (PFC) on the device if TC0 is not available. To fix this, ensure TC0 is\
  enabled when setting up DCB on your switch.\
  \
  DCB is a configuration Quality of Service implementation in hardware.\
  It uses the VLAN priority tag (802.1p) to filter traffic. That means\
  that there are 8 different priorities that traffic can be filtered into.\
  It also enables priority flow control (802.1Qbb) which can limit or\
  eliminate the number of dropped packets during network stress. Bandwidth\
  can be allocated to each of these priorities, which is enforced at the\
  hardware level (802.1Qaz).\
  \
  Adapter firmware implements LLDP and DCBX protocol agents as per 802.1AB\
  and 802.1Qaz respectively. The firmware based DCBX agent runs in willing\
  mode only and can accept settings from a DCBX capable peer. Software\
  configuration of DCBX parameters via dcbtool/lldptool are not supported.\
  \
  NOTE: Firmware LLDP can be disabled by setting the private flag\
  disable-fw-lldp on.\
  \
  The i40e driver implements the DCB netlink interface layer to allow\
  user-space to communicate with the driver and query DCB configuration for\
  the port.
- 请注意disable-fw-lldp上面提到的标志是上游i40e驱动程序提供的另一个ethtool功能。但是，从RHEL 7.5开始，RHEL7版本的i40e不包含此补丁，因此无法通过RHEL中的ethtool切换该功能。

===============最后解决================

 

经过这几天的测试，确认网卡MAC漂移问题是因为Dell服务器网卡在RHEL系统下LLDP协议默认开启造成，需要手动关闭该协议。

 

    解决办法如下：

 

    通过在RHEL系统下关闭对应网卡的LLDP功能

 

    

![[Technology_ALL_Linux 问题收集_045_RHEL7.x_bond问题_002.gif]]

 

    将该命令加入rc.local文件，使每次服务器启动都关闭对应网卡的LLDP协议。

 

    

![[Technology_ALL_Linux 问题收集_045_RHEL7.x_bond问题_003.gif]]

 

    关闭网卡LLDP协议下，通过交换机的LLDP功能可实现网卡的链路的自动切换：

    

    

![[Technology_ALL_Linux 问题收集_045_RHEL7.x_bond问题_004.jpg]]

 

    经测试，关闭网卡的LLDP协议后不在出现MAC漂移及丢包现象。
