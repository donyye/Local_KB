硬件平台有很多方式可以向上层软件或是系统传递硬件错误信息，而这些信息是的作用是硬件设计者和软件开发者的接口定义。

 

所以就有了APEI (Advanced Platform Error Interfaces) 高级平台错误接口

允许 BIOS 向操作系统报告错误。以前称为 WHEA。

它的结构简单来说有4张表：

BOOT Error Record Table (BERT)  引导错误记录表

Error Record Serialization Table (ERST)  错误记录序列化表

Error Injection Table (EINJ)   错误注入表

Hardware Error Source Table (HEST)  硬件错误源表

\--\>在 HEST 中定义了很多硬件相关的错误源和错误类型。如 MCE、PCI-E、GHES 等等。

 

BIOS\--\> APEI

\|\_\--\> HEST \--\> EDAC 向客户报告错误。

1:从TSR日志未发现内存报错事件，OS kernel记录内存single-bit ECC，并且已经被corrected ,It has been corrected by h/w and requires no further action

在 Linux 系统上，如果发生的MCE错误属于可以自动纠正的类型，那么系统保持继续运行，MCE错误日志会记录在一个ring buffer中（这个ring buffer通过设备文件/dev/mcelog来访问），

用 mcelog命令可以读取MCE日志，系统通常会通过cron任务或者mcelog.service把ring buffer中的MCE日志写入/var/log/message。(el7上默认使用mcelog.service启动的)

如果发生的MCE错误属于无法恢复的类型，那么系统会panic，错误信息会输出在终端上和message buffer里.

系统禁用mce：在/boot/grub/grub.conf 中加入以下内容：mce=off

SBE:

A Correctable Memory Error is a single bit error which occurs when a bit erroneously changes, from 1 to 0 or from 0 to 1,during a read or write operation. When the specific bit in error is identified, the error is corrected by complementing the erroneous bit. The correction of a single bit error typically happens on the fly using a parity bit as part of the ECC memory architecture.

可纠正的内存错误是在读取或写入操作期间当位错误地从 1 变为 0 或从 0 变为 1 时发生的单比特错误。 当识别出错误的特定位时，通过对错误位进行补码来纠正错误。 单个位错误的纠正通常使用奇偶校验位作为 ECC 存储器架构的一部分即时进行。

不知道是否正确？

SBE(Single bit Error)是系统在读数据过程中发现从内存读出来的数据和较验不匹配，从而发现一个bit有错误，并更正数据，这个时间就有可能导致CPU被锁中断过长时间

这个NMI是不可屏蔽中断，即有些内核进程长时间占用CPU导致，进程为了更新数据保持数据一致性会锁CPU来更新，但锁了CPU时间太长是不正常的，NMI就会报警  NMI handle  EDAC

现在的疑问就是如何界定哪些情况会触发NMI 中断，针对这个SBE 的case ，也就是说遇到SBE 的时候，势必要通过ECC 来更正数据，更正数据就需要时间

NMI watchdog会定期touch CPU，如果在这个数据更正的过程中NMI watchdog 在指定周期内touch 到了CPU, 日志就不会有体现，只会体现SBE 信息； 如果指定周期内没有touch 到CPU, 就会触发NMI 中断告警，机器体现为运行缓慢或卡住； 如果再长， 就有可能触发hard lockup 机器重启

而这些跟负载， 是否有重要数据在对应的SBE 数据块无关， 单纯就是跟数据更正的时间长短来决定，而这个更正的时间长短不好界定

 

====IPS xiaofeng===

ECC修复，BIOS会告知OS有修复发生，而OS会避开使用这一段被修复的内存（在开启EDAC的情况下。默认是开的)，如果系统disable EDAC，那系统也不会做改变避开它，但其实它是收到了一个已经修复好的信息。

如果ECC修复平凡或是指向相同的内存，那么对于一些使用内存敏感的程序会有性功影响。
