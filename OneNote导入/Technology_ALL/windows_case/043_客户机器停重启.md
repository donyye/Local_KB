客户机器停重启

2018年6月28日

15:02

- =====Issue=====

  Windows is rebooting repeatedly, the screen showed "Getting windows ready, do not turn off your computer" and reboot soon after it

   

  =====Troubleshooting=====

  1.  We booted the server with USB image into repair mode, system drive is E, checking windows patch with command:

  dism.exe /image:c:\\ /Get-Packages

  It seems we recently installed several patches and in pending status, issue happened since then.

  ![[Technology_ALL_windows_case_043_客户机器停重启_001.jpg]]

  1.  Try to revert patches with command: DISM /image:E:\\ /cleanup-image /revertpendingactions

  Then reboot but still failed.

  1.  Renamed E:\\windows\\winsxs\\pending.xml and ran command: sfc /scannow /offbootdir=E:\\ /offwindir=E:\\Windows

  Then reboot but still failed.

  1.  Run the following command to set advanced options:

  Bcdedit /set  advancedoptions on

  Bcdedit /set  recoveryenabled No

  1.  Remove the last patch using command, rebooted and still couldn't boot up

  dism.exe /image:e:\\ /remove-package /packagename:Package_for_RollupFix\~31bf3856ad364e35\~amd64\~\~9600.19036.1.6

  1.  Try to remove other patches, but failed with error, saying there's component store corruption
  2.  Also tried safe mode and last known good, all didn't work.
  3.  Finally, we replaced system and software hive, server booted up successfully:

  cd e:\\windows\\system32\\config

  Ren system system.old

  Ren Software software.old

  Copy E:\\windows\\system32\\config\\regback\\software D:\\windows\\system32\\config\\software

  Copy E:\\windows\\system32\\config\\regback\\system D:\\windows\\system32\\config\\system

  1.  After boot up, we fixed the component corruption:

  ![[Technology_ALL_windows_case_043_客户机器停重启_002.jpg]]

   

  The cause of this incident should be related to patch installation, and in April and May, monthly rollup patches all failed to install.

  And we detected component store corruption and fixed already, we think the server is currently healthy.
