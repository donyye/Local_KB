日志中没有明确 KB 提到的一些 return code 返回代码，这有可能kernel不同或是其它原因，如果需要进一步测试可以尝试如下操作，进一步判断是物理上的问题还是说一些有隐藏逻辑坏块的问题。

 

步骤：

1. 备份数据后使用 badblocks 命令检测坏块

\# badblocks -sv /dev/sdX \> badblocks.txt

信息会保持在 badblocks.txt 文件里。

\-\-\-\-\-\-\-\-\--例子：\-\-\-\-\-\-\-\-\-\-\-\--

\[root@r760xd2 \~\]# badblocks -sv /dev/sdb \> badblocks-sdb.txt

Checking blocks 0 to 1171521535

Checking for bad blocks (read-only test): done                                                 

Pass completed, 0 bad blocks found. (0/0/0 errors)

\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\--

 

2. 使用 dd 的方式来多磁盘所有block写0（数据会被清楚）

\# dd if=/dev/zero of=/dev/sdX bs=1M status=progress

目的是为了确认所有block，但是这个过程时间会比较久。会有进度显示。

\-\-\-\-\-\-\-\-\--例子：\-\-\-\-\-\-\-\-\-\-\-\--

\[root@r760xd2 \~\]# time dd if=/dev/zero of=/dev/sdb bs=1M status=progress

1199567798272 bytes (1.2 TB, 1.1 TiB) copied, 5982 s, 201 MB/s

dd: error writing \'/dev/sdb\': No space left on device

1144065+0 records in

1144064+0 records out

1199638052864 bytes (1.2 TB, 1.1 TiB) copied, 6033.75 s, 199 MB/s

\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\--

 

3. 重新使用 mkfs.ext4 方面进行格式化后挂载，然后再继续观察是否还会有相同issue出现。

 

建议相似问题的case可以使用相同的方式进行尝试。
