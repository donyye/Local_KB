一些性能命令介绍：

 

- PIDSTAT

pidstat 命令属于Linux系统资源分析工具（sysstat包）的一部分，用于监控进程性能。

 

下面是具体拆分：

命令解释：

pidstat -p ALL 3600 60 -r

 

1)pidstat

用于统计进程/线程对系统资源的占用情况的工具。

属于sysstat软件包的一部分，常用于系统性能监控。

 

2)-p ALL

作用范围：

-p标志指定监控的进程（Process ID）。

ALL表示监控所有当前运行的进程（包括系统后台进程）。

 

3)3600 60

定时配置：

3600：统计周期总时长总时长（单位：秒）。

60：采样间隔时间（单位：秒）。

说明：该指令会监测60分钟（3600秒）时间窗口，每60秒采样并输出一次数据。

 

4)-r

监控类型：

[  -r]选项表示监控内存性能指标包括：

RSS：进程实际占用的物理内存量。

VSZ：进程虚拟内存量（包含磁盘Swap使用情况）。

页缺（Page faults）：内存分页缺页次数（minor/major）。

 

典型使用场景：

1)诊断内存泄露进程

例如怀疑是应用进程持续占用内存或未正确释放。

2)发现内存异常膨胀行为

如某进程内存占用异常激增后未回降。

3)监测资源消耗趋势

在指定时段（如上例子60分钟内）实时查看内存波动情况。

 

注意事项：

1)该命令会输出大量数据到终端屏或文件（需重定向）。

2)安装需求：确保已安装sysstat包（Linux基本工具包）。 bash sudo apt-get install sysstat \# Debian/Ubuntu sudo yum install sysstat \# CentOS/RHEL

如需进一步验证该指令或输出结果格式，可手动尝试执行此指令。

- 内存追踪

1\) top Shift + M

 

2\) ps aux \--sort=-rss \| head

其中：

RSS（Resident Set Size）= 真实使用的物理内存

排第一的就是"最吃内存的那个进程"

 

3\) pmap -x 1234 \| grep total

每隔几分钟重复一次：

如果 total 持续增长 → 极可能泄漏。

 

4) 使用 watch 监控 RSS（最简单）

watch -n 2 \"ps -o pid,rss,comm -p 1234\"

输出会每 2 秒更新一次。

观察重点：

RSS 数值 是否持续增长且从不下降？

业务负载减少时 RSS 有没有下降？

 

5) 创建一个追踪脚本：

while true; do

    date \>\> memory.log

    ps -o pid,rss,comm -p 1234 \>\> memory.log

    echo \"\-\-\-\--\" \>\> memory.log

    sleep 5

done

运行 10 分钟～几小时，然后分析 memory.log。

 

6\) smem -r -p 1234

它能显示：

USS（唯一使用的内存）

PSS（实际占用 + 共享页分摊）

RSS（物理内存）

PSS 最能看真实内存需求。
