如果你升级了新模块发现有问题，想用回来的模块，方法是：

删除新的模块

\# rm -rf /lib/modules/2.6.18-274.el5/updates/bnx2.ko

\# depmod -a    \--\> 详细解释"[http://man.linuxde.net/depmod"](http://man.linuxde.net/depmod%E2%80%9D)

\# 再使用 modinfo bnx2 查看是否用回原来模块了。

如果运行命令后还是不能切换模块，尝试把旧的模块删除或移动它。

编译好模块后，进入模块的目录里。如 cd /lib/modules/3.xxxxxx/update/ 。然后运行depmod -a，系统就会匹配这里的模块作为首选模块。

或许你可以吧新upgrade的driver 移动到 /lib/modules/2.6.18-274.el5/kernel/drivers/net  模块默认目录下，然后再运行depmod -a 命令。

depmod -a 主要是扫描模块，重新整理等。

其实他会重新在下面文件里整理关系：

/lib/modules/2.6.18-274.el5/modules.dep

如果你删除里面的一个模块依赖关系，depmod -a 会马上再建立回来。

我们后台也在实验室模拟了您这边的现像， 因为kernel 4.4 不带受支持的megaraid_sas driver. 请根据我们工程师建议完成如下操作:

 

Please follow the below steps to replace the driver.

 

Copy the megaraid_sas.ko into the server let say maybe /tmp/.

 复制 megaraid_sas.ko 进入服务器，比如maybe /tmp/。

 

Backup/move the current megaraid_sas driver.

备份/移动当前的megaraid_sas驱动程序。

 

\# mv /lib/modules/4.4.237-1.el7.elrepo.x86_64/kernel/drivers/scsi/megaraid/megaraid_sas.ko /tmp/megaraid_sas.ko.bak

\# mv /tmp/megaraid_sas.ko /lib/modules/4.4.237-1.el7.elrepo.x86_64/kernel/drivers/scsi/megaraid/

 

Backup and rebuild initramfs 备份和重建initramfs

\# cp /boot/initramfs-4.4.237-1.el7.elrepo.x86_64.img /boot/initramfs4.4.237-1.el7.elrepo.x86_64.bak.\$(date +%m-%d-%H%M%S).img

\# dracut -f -v \--add-drivers megaraid_sas \--kver=4.4.237-1.el7.elrepo.x86_64

 

Since we have an issue with mgag200 driver preventing it from boot as well, we need to set the boot parameter to include mgag200.modeset=0 our customer can do it at

由于我们有一个问题，mgag200驱动也无法启动，我们需要设置启动参数，包括mgag200.modeset=0，我们的客户可以在以下地方进行设置 

\[root@localhost \~\]# vi /etc/default/grub

GRUB_CMDLINE_LINUX=\"crashkernel=auto spectre_v3=retpoline rd.lvm.lv=centos/root rd.lvm.lv=centos/swap rhgb mgag200.modeset=0\"

 

After completed we make a new grub config

 

\[root@localhost \~\]# grub2-mkconfig -o /boot/efi/EFI/centos/grub.cfg
