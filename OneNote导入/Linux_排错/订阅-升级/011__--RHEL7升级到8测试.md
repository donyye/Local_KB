根据Redhat KB，升级需要跟新到 7.9 后再向上升级。

![[订阅-升级_011__--RHEL7升级到8测试_002.png]]

 

 

通过原位升级方式，把 RHEL 7 升级到 RHEL 8 的过程总结如下：

 

1. 计划升级

查看系统要求和限制。确定您的系统是否适合原位升级，或者您是否应该执行 RHEL 8 的全新安装。

需要注意的是：跨版本升级，有些模块或是包在新版本上已经不再使用或被淘汰了，有些模块是一定要被删除，否则是无法完成删除，所以需要确认清楚是否符合你当前的环境要求，比如 Python版本在7和8里使用的就不一样。

 

2. 准备升级

在开始升级过程前，请完成所需的准备步骤，包括创建 RHEL 7 系统的备份。\
1) 添加软件包

\[root@localhost \~\]# subscription-manager repos \--enable rhel-7-server-rpms

Repository \'rhel-7-server-rpms\' is enabled for this system.

 

\[root@localhost \~\]# subscription-manager repos \--enable rhel-7-server-extras-rpms

Repository \'rhel-7-server-extras-rpms\' is enabled for this system.

 

\[root@localhost \~\]# subscription-manager repos \--list-enabled \| grep \"\^Repo ID\"

Repo ID:   rhel-7-server-extras-rpms

Repo ID:   rhel-7-server-rpms

 

2）先把RHEL7升级到最新

\[root@localhost \~\]# yum update -y

 

升级完成后重启系统查看kernel版本已经是 7.9 最新版本。

\[root@localhost \~\]# uname -r

3.10.0-1160.119.1.el7.x86_64

 

安装 leapp 工具

\[root@localhost \~\]# yum install leapp-upgrade

 

3. 运行并查看预升级报告

运行预升级工具来生成一个报告，该报告总结了在升级之前必须解决的潜在问题。根据发现的问题的严重性和影响以及解决问题所需的工作量，请继续执行以下结果之一：

\* 修复发现的问题并应用推荐的解决方案。重新运行预升级工具，以验证是否所有严重问题都已解决。您可能需要运行预升级报告，并在系统准备好升级之前多次解决发现的问题。

\* 切换到全新安装的 RHEL 8 ，而不是继续原位升级。

更新前先通过命令生成报告：

\[root@localhost \~\]# leapp preupgrade \--target 8.10

以下是运行后出现的信息截图：

info ： 对系统或应用程序没有预期影响的信息。

 

 

4. 执行原位升级

执行到 RHEL 8 的升级，并验证升级是否已正确完成。如果升级遇到无法解决的问题，请执行到 RHEL 7 备份的回滚。（回滚是需要通过lvm或VM快照的方式进行）

1）开始执行升级到 8.10 (需要比较长的时间)

\[root@localhost \~\]# leapp upgrade \--target 8.10

5. 执行升级后步骤

执行所需的升级后步骤，以确保 RHEL 8 系统已正确建立。

1）从 exclude 列表中删除所有软件包：

\[root@localhost \~\]# yum config-manager \--save \--setopt exclude=\'\'

Updating Subscription Management repositories.

 

This system is registered with an entitlement server, but is not receiving updates. You can use subscription-manager to assign subscriptions.

 

2）删除剩余的 RHEL 7 软件包，包括剩余的 Leapp 软件包

\[root@localhost \~\]# cd /lib/modules && ls -d \*.el7\*

3.10.0-1127.el7.x86_64  3.10.0-1160.119.1.el7.x86_64

 

多个kernel，每个kernel 都要运行

\[root@localhost modules\]# \[ -x /usr/sbin/weak-modules \] && /usr/sbin/weak-modules \--remove-kernel 3.10.0-1127.el7.x86_64

 

\[root@localhost modules\]# \[ -x /usr/sbin/weak-modules \] && /usr/sbin/weak-modules \--remove-kernel 3.10.0-1160.119.1.el7.x86_64

 

\[root@localhost modules\]# /bin/kernel-install remove 3.10.0-1127.el7.x86_64 /lib/modules/3.10.0-1127.el7.x86_64/vmlinuz

 

\[root@localhost modules\]# /bin/kernel-install remove 3.10.0-1160.119.1.el7.x86_64 /lib/modules/3.10.0-1160.119.1.el7.x86_64/vmlinuz

 

找到剩余的 RHEL 7 软件包：

[\[root@localhost \]#] [rpm -qa \| grep -e \'\\.el\[67\]\' \| grep -vE \'\^(gpg-pubkey\|libmodulemd\|katello-ca-consumer)\' \| sort]

doxygen-1.8.5-4.el7.x86_64

flite-1.3-22.el7.x86_64

kernel-3.10.0-1127.el7.x86_64

kernel-3.10.0-1160.119.1.el7.x86_64

leapp-0.17.0-2.el7_9.noarch

leapp-upgrade-el7toel8-0.20.0-13.el7_9.noarch

libchamplain-0.12.16-2.el7.x86_64

libchamplain-gtk-0.12.16-2.el7.x86_64

libIDL-0.8.14-8.el7.x86_64

python2-leapp-0.17.0-2.el7_9.noarch

ustr-1.0.4-16.el7.x86_64

 

从 RHEL 8 系统中删除剩余的 RHEL 7 软件包，包括旧的内核软件包和 kernel-workaround 软件包。要确保维护 RPM 依赖项，请在执行操作时使用 YUM 或 DNF。在接受之前检查事务，以确保没有任何软件包被意外删除。 

\[root@localhost \]#yum remove kernel-workaround \$(rpm -qa \| grep \\.el7 \| grep -vE \'gpg-pubkey\|libmodulemd\|katello-ca-consumer\')

 

删除任何剩余的空目录：

\[root@localhost \~\]# rm -r /lib/modules/\*el7\*

rm: cannot remove \'/lib/modules/\*el7\*\': No such file or directory

 

3）可选：从系统中删除所有剩余的与升级相关的数据：

[\[root@localhost \~\]# rm -rf /var/log/leapp /root/tmp_leapp_py3 /var/lib/leapp\
]\# 删除这些数据可能会限制红帽支持调查并故障排除升级后问题的能力。 

 

 

4）将旧的救援内核和初始 RAM 磁盘替换为当前的内核和磁盘：

\[root@localhost \]# rm /boot/vmlinuz-\*rescue\* /boot/initramfs-\*rescue\*

rm: remove regular file \'/boot/vmlinuz-0-rescue-44088e4124034d2aaa83f18c1270ba25\'? y

rm: remove regular file \'/boot/initramfs-0-rescue-44088e4124034d2aaa83f18c1270ba25.img\'? y

 

\[root@localhost \]# /usr/lib/kernel/install.d/51-dracut-rescue.install add \"\$(uname -r)\" /boot \"/boot/vmlinuz-\$(uname -r)\"

 

验证

1）验证旧内核是否已从引导装载程序条目中删除： 

\[root@localhost \]# grubby \--info=ALL \| grep \"\\.el7\" \|\| echo \"Old kernels are not present in the boot loader.\"

Old kernels are not present in the boot loader.

 

2）验证已为当前内核创建了之前删除的救援内核和救援初始 RAM 磁盘文件：

\[root@localhost \]# ls /boot/vmlinuz-\*rescue\* /boot/initramfs-\*rescue\*

/boot/initramfs-0-rescue-44088e4124034d2aaa83f18c1270ba25.img  /boot/vmlinuz-0-rescue-44088e4124034d2aaa83f18c1270ba25

 

\[root@localhost \]# lsinitrd /boot/initramfs-\*rescue\*.img \| grep -qm1 \"\$(uname -r)/kernel/\" && echo \"OK\" \|\| echo \"FAIL\"

OK

 

3）验证救援引导条目是否指向现有救援文件。请查看 grubby 输出： 

\[root@localhost \~\]# grubby \--info \$(ls /boot/vmlinuz-\*rescue\*)

root=\"UUID=1973770d-22a3-4f10-bb33-6ad279a3cf20\"

initrd=\"/boot/initramfs-0-rescue-44088e4124034d2aaa83f18c1270ba25.img \$tuned_initrd\"

id=\"44088e4124034d2aaa83f18c1270ba25-0-rescue\"
