案例12: 无法正常启动

2025年9月17日

14:49

问题描述：\
客户系统 RHEL8，系统重启，硬件自检完成，但是后续会黑屏，无法到 kernel 加载界面，过一会后会自动又重启，反复这个过程。

 

检测过程：

1）可以通过 recuse 模式进入，能看到客户使用的是 BIOS 引导模式，GRUB文件都在。

2）修改成 UEFI 模式后重启启动，不成功。

3）重新安装 GRUB2 时候也出现了提示格式不是 BIOS 而是 GPT，发现不对，不应该是GPT格式。

![[Linux引导修复_021_案例12_ 无法正常启动_001.png]]

 

4）使用"parted -s /dev/sdb unit s print" 看到 sdb ，发现真是 GPT 格式。

如下图 

![[Linux引导修复_021_案例12_ 无法正常启动_002.png]]

因为BIOS的引导格式应该是 DOS，所以怀疑之前有对系统 sdb，也就是存储 boot 的地方改成了 GPT，最终导致了这个问题。

 

5）尝试查找看是否有另外一台相同的配置的机器，看一下格式和分区的起始位和结位置。

 

6）使用"hexdump -C /dev/sdb1 \| more" 来对比正常和不正常的机器，看是否一样。\
\
最后可以采取的方法：(先备份总要数据)

1）使用命令来修改 sdb 到原来格式，

把 sda 改成 MBR(dos) 分区

\# parted -s /dev/sdb mklabel msdos

 

2）如果分区有变化，再对比正常的，看是否能改过来

非交互手动修改 Start 与 End，如下：

\# parted -s /dev/sda unit s mkpart primary 2048 1050623

 

 

如果都无法修复，那只能重新安装系统。

这个问题有可能是客户的误操作导致，把sdb改成了GPT格式。
