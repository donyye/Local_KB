rhel7: system boot stops with \"Hardware error from APEI Generic Hardware Error Source: 0\"

KB：

<https://access.redhat.com/solutions/695873>

 

rhel7：系统启动停止并显示"来自 APEI 通用硬件错误源的硬件错误：0"

 

尝试启动 RHEL7 时停止并显示："来自 APEI 的硬件错误，通用硬件错误源：0"

虽然 RHEL6.5 在我的系统上安装成功，但启动 RHEL7 时出现如下情况：

 

[\[Hardware Error\]: Hardware error from APEI ]Generic Hardware Error Source[: 0\
\[Hardware Error\]: APEI generic hardware error status\
\[Hardware Error\]: severity: 1, fatal\
\[Hardware Error\]: section: 0, severity: 1, fatal\
\[Hardware Error\]: flags: 0x01\
\[Hardware Error\]: primary\
\[Hardware Error\]: fru_text: UncorrectedErr\
\[Hardware Error\]: section_type: PCIe error\
\[Hardware Error\]: command: 0x0010, status: 0x0146\
\[Hardware Error\]: device_id: 0000:00:00.5\
\[Hardware Error\]: slot: 0\
\[Hardware Error\]: secondary_bus: 0x00\
\[Hardware Error\]: vendor_id: 0x19a2, device_id: 0x0710\
\[Hardware Error\]: class_code: 000002\
Kernel panic - not syncing: Fatal hardware error!\
Rebooting in 30 seconds..]

 

 

虽然 RHEL6.5（及更早的次要版本）会评估 ERST、HEST 和 EINJ，但它们不会评估 BERT。启动 RHEL7 并出现上述消息可能表明 BERT 包含错误。这可能是过去的错误，因此应测试硬件以确保其没有故障，然后从 BERT 中删除/清除该条目。

 

如果硬件没有故障，则可能存在兼容性问题，需要禁用通用硬件错误源 (GHES) 检查。要禁用 GHES，请添加ghes.disable=1从 grub 屏幕进入内核命令行，查看系统是否可以启动。

 

为了使此更改在将来的重新启动时保持不变，请添加 ghes.disable=1 到 GRUB_CMDLINE_LINUX在/etc/default/grub文件，然后执行grub2-mkconfig -o /boot/grub2/grub.cfg重建 grub 配置文件。

 

 

原因：

根据 ACPI 4.0a 规范，APEI 由四个独立的表组成：

错误记录序列化表 (ERST)

引导错误记录表 (BERT)

硬件错误源表 (HEST)

错误注入表（EINJ）

虽然 RHEL6.5（及更早的次要版本）会评估 ERST、HEST 和 EINJ，但它们不会评估 BERT。启动 RHEL7 并出现上述消息可能表示 BERT 包含错误。
