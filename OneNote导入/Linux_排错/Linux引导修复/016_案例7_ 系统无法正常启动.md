案例7: 系统无法正常启动

2024年5月14日

16:36

系统RHEL9.2

 

系统启动后一直停在此信息上，无法正常进入系统。

System hangs after displaying \"systemd-journald\[xx\]: Received SIGTERM from PID 1 (systemd)\"

![[Linux引导修复_016_案例7_ 系统无法正常启动_001.png]]

 

查找KB，是因为lib库有问题。

<https://access.redhat.com/solutions/3911291>

 

客户回顾，做了下面修改操作导致。

![[Linux引导修复_016_案例7_ 系统无法正常启动_002.png]]

 

当时应该尝试把这些链接都删除掉然后再进行重启尝试。

或者可以使用 rpm -Va 来验证一下

 

进入安全模式后

出现这种问题会导致很多命令无法使用。

![[Linux引导修复_016_案例7_ 系统无法正常启动_003.png]]

 

![[Linux引导修复_016_案例7_ 系统无法正常启动_004.png]]

 

最后客户选择重新安装系统。

 

\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\--

介绍一下 rpm -Va 

命令用于验证系统上所有已安装的 RPM 包的完整性。它会检查每个文件是否与 RPM 数据库中的信息匹配，并报告任何差异。这些差异可能包括文件的大小、权限、类型、所有者、组、MD5 校验和、最后修改时间等。

 

 

[\[root@localhost lib64\]# rpm -Va]

S.5\....T.  c /etc/cups/cups-browsed.conf

\....L\....  c /etc/pam.d/fingerprint-auth

\....L\....  c /etc/pam.d/password-auth

\....L\....  c /etc/pam.d/postlogin

\....L\....  c /etc/pam.d/smartcard-auth

\....L\....  c /etc/pam.d/system-auth

\....L\....    /lib64/libm.so.6

\.....UG..  g /var/run/avahi-daemon

S.5\....T.  c /etc/yum/pluginconf.d/langpacks.conf

missing     /run/gluster

.M\...\....  g /var/lock/iscsi

.M\...\....  g /var/lock/iscsi/lock

missing     /var/run/pluto

missing     /run/gdm

missing     /var/run/pulse

S.5\....T.  c /etc/sysconfig/authconfig

 

L 代表链接文件，说明 [ /lib64/libm.so.6] 这个裤的文件链接有被修改过，这会导致系统启动时出现问题。

<https://access.redhat.com/solutions/183083>

 

\# rpm -Va 2\>/dev/null \>rpmva.log

\# yum reinstall \$(rpm -qf \$(awk \'(/\^..5/ && \$2 != \"c\") \|\| /\^missing/ \' rpmva.log) \| sort -u)
