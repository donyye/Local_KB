1. 需要知道系统停留在那个位置上。

1）通过启动系统引导启动的 quit 选型来观察。

2）根据具体情况来判断是什么问题。

3）如果能看到加载 kernel 选项，说明分区表大概率没问题。

 

2. 如果系统分区表有问题

1）检查时BIOS分区还是UEFI分区

2）通过 rescue 模式进入，通过hexdump命令来检查

3）如果分区有错误可用通过 gdisk 或是 parted来修复。

目前 gdisk 有测试过可用修复成功

4）修复分区也可用通过加载 SLI 方式进行。

=====================

 

当救援模式尝试把挂载点绑到 /mnt/sysimage 时，有时会失败，或是成功了但是有些命令无法使用。

比如：

执行 sosreport 命令时，得到以下报错信息：

error on sosreport: no such file or directory /dev/urandom

或者一些 ls 命令可以使用，但是 lsblk 等命令会出现下面错误

failed to access sysfs directory /sys/dev/block no such file or directory

这个时候 /dev/ 下也看不到设备。

 

这时候，需要如下操作。请先输入下面的命令来退出 chroot 环境并挂载必要的数据:

\# exit   \<\--执行这个命令可以退出 chroot 环境\
\# mount -o bind /dev /mnt/sysimage/dev\
\# mount -o bind /sys /mnt/sysimage/sys\
\# mount -o bind /proc /mnt/sysimage/proc\
\# chroot /mnt/sysimage

 

 

\# systemctl \--failed -l[  \--\> ]可查看那些进程启动是失败的

\# journalctl -xe \_SYSTEMD\_=httpd.service

如果系统启动黑屏，IDRAC控制台无法显示，但是系统使用正常，可以尝试启动时加 "nomodeset"参数。

这个参数常用于解决图形驱动相关的问题，尤其是在没有正确的图形驱动或者显卡驱动不兼容时。它会禁用内核的显卡模式设置。
