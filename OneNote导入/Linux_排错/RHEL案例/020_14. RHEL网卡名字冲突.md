Cause

Help CauseSummarize the issue's root cause, and include technical details for the designated audience.\
帮助原因总结问题的根本原因，并为指定受众提供技术细节。

 

In RHEL default naming scheme, it will take both NICs with slot 1 to create the NIC name that will cause both NICs has the same naming with ens1f0 to ens1f3. So 4 ports which came first will be renamed to ens1f0 to ensf3 while remaining 4 ports have conflict name will keep original ethX. That will result as following.\
在RHEL默认命名方案中，将使用插槽为1的两个NIC来创建NIC名称，这将导致两个NIC具有相同的命名，从ens1f0到ens1f3。因此，首先出现的4个端口将被重命名为ens1f0到ensf3，而其余4个端口具有冲突名称，将保留原始ethX。这将导致以下结果。\
 

4: ens1f0: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

5: eth1: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

6: eth2: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

7: ens1f3: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

8: eth4: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

9: ens1f1: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

10: ens1f2: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

11: eth7: \<NO-CARRIER,BROADCAST,MULTICAST,UP\> mtu 1500 qdisc mq state DOWN group default qlen 1000

 

Resolution

Help ResolutionSummarize the steps used to address the issue and include any detailed instructions on required actions.

帮助解决方案总结用于解决问题的步骤，并包括有关所需操作的任何详细说明。

In RHEL9.5, RHEL introduced \"rhel-9.5\" naming scheme as following which never generate slot name when a PCI bridge is detected..

在RHEL9.5中，RHEL引入了"RHEL-9.5"命名方案，如下所示，当检测到PCI桥时，该方案从不生成插槽名称..

 

\# man 7 systemd.net-naming-scheme

       rhel-9.0

           Since version v247 we no longer set ID_NET_NAME_SLOT if we detect that a PCI device associated with a slot is a PCI bridge as that

           would create naming conflict when there are more child devices on that bridge. Now, this is relaxed and we will use slot information

           to generate the name based on it but only if the PCI device has multiple functions. This is safe because distinct function number is a

           part of the device name for multifunction devices.

 

       rhel-9.1

           Same as naming scheme rhel-9.0.

 

       rhel-9.2

           Same as naming scheme rhel-9.0.

 

       rhel-9.3

           Naming was changed for SR-IOV virtual device representors.

 

           The \"rslot\" suffix was added to differentiate SR-IOV virtual device representors attached to a single physical device interface.

 

       rhel-9.4

           Same as naming scheme rhel-9.3.

 

       rhel-9.5

           Never generate a slot name when a PCI bridge is detected.

 

           Since version \"rhel-9.0\", we have generated slot-based names for PCI multifunction devices, because we assumed that it is enough to

           use function numbers to distinguish between devices. However, name conflict can occur if these devices are not children of the same

           PCI bridge, e.g. there are multiple PCI bridges in the same slot.

 

       By default rhel-9.0 is used.

 

So the workaround is to enable rhel-9.5 naming scheme if the OS is RHEL 9.5.

\# grubby \--update-kernel=ALL \--args=net.naming-scheme=rhel-9.5

Or using Dell biosdevname naming scheme by disabling secure boot in BIOS and enable biosdevname in kernel parameter.

\# grubby \--update-kernel=ALL \--args=biosdevname=1

Notes: once changed the NIC naming scheme, the NIC name will be changed at next reboot. The existing network configuration will not apply to the new name of the NIC. You might lose network connectivity at next reboot until the network configuration was set with the new NIC name.

因此，如果操作系统是rhel 9.5，解决方法是启用rhel-9.5命名方案。

\# grubby \--update-kernel=ALL \--args=net.naming-scheme=rhel-9.5

或者通过在BIOS中禁用安全引导并在内核参数中启用biosdevname来使用Dell biosdevnname命名方案。

\# grubby \--update-kernel=ALL \--args=biosdevname=1

注意：一旦更改了NIC命名方案，NIC名称将在下次重新启动时更改。现有网络配置将不适用于NIC的新名称。在使用新的NIC名称设置网络配置之前，您可能会在下次重新启动时失去网络连接。
