规则导致的网卡命名冲突与异常变化说明

 

 

1. 概要

在 Red Hat Enterprise Linux 及其衍生版本（含 Rocky / Alma / CentOS Stream 等）的默认配置下，

网卡名称（NIC Name）由系统自动依据硬件拓扑生成。

该机制称为：

Predictable Network Interface Names（systemd 可预测网卡命名规则）

其目的是保证即使更换网卡位置，也能根据硬件信息生成唯一、稳定的名称，如：

eno1, ens3f0, enp129s0f0

但在某些硬件架构下（例如多块网卡共用同一 PCIe Slot，或主板 ACPI/DMI 信息异常），

此机制可能失效，导致命名冲突或随机变化，例如：

- ens1f0 ↔ eth0
- eno1 → eno113
- 部分接口名重复或缺失

本文汇总了这些常见的命名异常场景及处理方案。

 

2. 命名规则机制概览

systemd/net命名规则由以下来源决定，顺序取决于 NamePolicy 配置（默认如下）：

NamePolicy=keep kernel database onboard slot path

| 来源                                            | 命名前缀 | 含义                                                                                                                                                                                             | 示例                                                                                                                                                                                           |
+-----------------------------------------------------------------------------+--------------------------------------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| onboard                                         | eno                                  | [使用] BIOS/ACPI 提供的板载接口编号                                                                                               |                                                                                                                                                                                                                            |
+-----------------------------------------------------------------------------+--------------------------------------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| slot                                            | ens                                  | [使用]）                                                                                                                                                                     |                                                                                                                                                                                                                            |
+-----------------------------------------------------------------------------+--------------------------------------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| path                                            | enp                                  | 使用 PCI 设备路径（Bus、Slot、Function） |                                                                                                                                                                                                                            |
+-----------------------------------------------------------------------------+--------------------------------------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| [mac]                                                     |                                      |                                                                                                                                                                                                                              |                                                                                                                                                                                                                            |
|                                                                             |                                      |                                                                                                                                                                                                                              |                                                                                                                                                                                                                            |
|                                                                             |                                      |                                                                                                                                                                                                                              |                                                                                                                                                                                                                            |
+-----------------------------------------------------------------------------+--------------------------------------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+

✅ 结论：

eno / ens / enp / enx 前缀代表名称来源。

其中 onboard 和 slot 最容易受 BIOS 或 PCI 架构影响而导致命名冲突。

 

 

3. 问题类型分类与案例分析

情形 A：多块 PCIe 网卡挂在同一 PCI 桥下导致命名冲突

 

适用机型：

部分 Intel E810 / X710、Dell R760、HP ProLiant 等服务器。

 

现象：

某台服务器安装多块网卡，例如两张 Intel E810 / X710，

它们连接在同一物理 PCI Slot，但属于不同的 PCIe Bridge。

结果：

- 两张卡的 Slot ID 相同（例如都为 Slot 1）；
- 生成相同的命名前缀 ens1f0\~f3；
- 后加载的网卡因命名冲突而回退为旧式命名 ethX；
- 每次重启网卡名顺序不固定。

 

示例输出：

ens1f0

eth1

eth2

ens1f3

eth4

ens1f1

ens1f2

eth7

 

根因分析：

- systemd 使用 "slot-based naming"；
- 多 PCI bridge 同属一个 Physical Slot → Slot ID 重复；
- 导致 ID_NET_NAME_SLOT 冲突。

 

解决方案：

1.  修改默认命名策略优先级，使 path 优先于 slot：\
    mkdir -p /etc/systemd/network/\
    cp /usr/lib/systemd/network/99-default.link /etc/systemd/network/\
    vi /etc/systemd/network/99-default.link\
    \
    修改为：\
    NamePolicy=kernel database onboard path slot\
    AlternativeNamesPolicy=database onboard path slot\
    \
    ✅ 原理：PCI 路径唯一，slot 可重复，path 优先即可避免冲突。

 

1.  （RHEL 9.5+ 推荐）启用新的命名 scheme：\
    grubby \--update-kernel=ALL \--args=net.naming-scheme=rhel-9.5
    - 从 RHEL 9.5 起，系统检测到 PCI Bridge 时不再生成 slot 名，从机制上杜绝该问题。
2.  （可选）启用 BIOS 命名模式：\
    yum install -y biosdevname\
    grubby \--update-kernel=ALL \--args=biosdevname=1

 

情形 B：板载口编号异常，eno1 / eno2 变成 eno113 / eno114

 

适用机型：

部分 Dell / HPE / Supermicro 主板（尤其在 BIOS 升级或冷启动后）

 

现象：

原本板载网卡命名为：

eno1

eno2

某次重启后却变为：

eno113

eno114

 

根因：

- "onboard" 命名依赖 BIOS/ACPI DMI 表中的 Onboard Index；
- BIOS 报告异常（或 DMI 表更新），Index 变成大数字 113、114；
- 因此 systemd 生成的名称带上了错误的编号。

 

关键点：

Type 41 (\"Onboard Devices Extended Information\")

  Index = 113

 

解决方案：

1.  禁止 systemd 使用 "onboard" 命名策略：\
    mkdir -p /etc/systemd/network/\
    cp /usr/lib/systemd/network/99-default.link /etc/systemd/network/\
    vi /etc/systemd/network/99-default.link\
    \
    修改为：\
    NamePolicy=kernel database path slot\
    \
    去掉 onboard 即可避免 BIOS index 干扰。
2.  或固定网卡名称（推荐）：\
    在 /etc/udev/rules.d/70-persistent-net.rules（或 NM 配置中）中直接绑定设备 MAC：\
    SUBSYSTEM==\"net\", ACTION==\"add\", ATTR==\"a0:36:9f:xx:xx:xx\", NAME=\"mgmt0\"

 

情形 C：系统版本导致命名不一致

 

现象：

不同 Red Hat 版本间网卡命名规则略有差异。

 

  --------------------------------------------------------------------------------------------------------------- ------------------------------------------------------------- ------------------------------------------------------------------------------------------------------------------------------------------------------
  [命名]{style="font-weight:                                                                                      [RHEL ] Scheme版本                                                                                           font-family:\"Microsoft YaHei\""}                           
  rhel-9.0 \~ rhel-9.4                                                            默认策略                                                      使用 Slot 命名；多 Bridge 下可能冲突

解决方式：

统一开启 RHEL 9.5 方案：

grubby \--update-kernel=ALL \--args=net.naming-scheme=rhel-9.5

5. 建议的长期策略

1.  优先使用 path 命名规则：
    - 唯一性最高；
    - 不依赖 BIOS/PCI slot；
    - 最适合稳定的服务器环境。
2.  在多网卡系统上禁用 slot/onboard 命名：\
    NamePolicy=kernel database path
3.  RHEL 9.5 及以上版本直接使用新命名方案：\
    grubby \--update-kernel=ALL \--args=net.naming-scheme=rhel-9.5
4.  在需要固定名称的系统上手动生成 persist-rules（绑定 MAC）。

 

 

6. 附录：常用命令

查看每个网卡的命名信息：

udevadm info /sys/class/net/\<interface\> \| egrep \"ID_NET_NAME\|ID_PATH\|ID_SLOT\"

 

查看有效命名方案：

man 7 systemd.net-naming-scheme

 

查看 BIOS 提供的板载网络设备索引：

dmidecode -t 41

💡 最后一句话总结：

"eno1 变成 eno113" 与 "ens1f0 ↔ ethX 冲突" 属于 同一系统命名逻辑问题的不同表现。

前者是 BIOS onboard 索引异常，后者是 PCI slot 重复。

都可通过 调整 NamePolicy 优先级 或 启用 RHEL 9.5 命名方案 来彻底避免。
