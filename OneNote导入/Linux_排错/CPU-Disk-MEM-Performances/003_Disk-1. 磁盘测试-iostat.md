磁盘IO 测试命令\
\# iostat -zxmd 1

![[CPU-Disk-MEM-Performances_003_Disk-1. 磁盘测试-iostat_001.png]]

RHEL7.9 上运行，通过简单的拷贝大文件，比如 40G ，来进行测试磁盘性能。

\-\-\-\-\-\--各项数值含义\-\-\-\-\-\--

Device[               ]设备名称

rrqm/s[                ]每秒合并的读操作数

wrqm/s[               ]每秒合并的写操作数[  ]

r/s[                   ][     ]每秒完成的读操作数

w/s[                   ][   ]每秒完成的写操作数

rMB/s[                 ]每秒读数据量 (MB/s) [  ]\--\> 读带宽利用情况

wMB/s[                ]每秒写数据量 (MB/s)[  ]\--\> 写带宽利用情况

avgrq-sz[              ]平均请求扇区数

avgqu-sz[              ]平均请求队列长度

await[                 ][   ]平均I/O请求等待时间 (ms) 毫秒

svctm[                 ][  ]平均I/O请求平均延时时间 (ms) 毫秒，这表示请求在磁盘上获得服务所花费的时间。

%util[                 ][   ]cpu利用率。接近100%的值表示磁盘利用率非常高,可能会导致磁盘饱和

 

这两个值反映了磁盘实际的读写带宽利用情况。例如,如果看到 rMB/s = 100.00,表示该磁盘每秒从磁盘读取了100MB的数据。

rMB/s 表示每秒从设备读取的数据量(MB/s)

wMB/s 表示每秒写入到设备的数据量(MB/s)

 

从上面的例子可以看出，awit 很高，一般这个数值不超过 20，最佳是10已内。

超过30ms就会对性能造成一定影响;而60ms以上则意味着磁盘严重瓶颈存在。

 

而且这个是 NVME的盘，道理上会更好。这个测试最终也系统版本有关系，RHEL8.9 性能会更好，在20已内。

![[CPU-Disk-MEM-Performances_003_Disk-1. 磁盘测试-iostat_002.png]]

 

总 IOPS = r/s + w/s

 

磁盘性功不佳要考虑的因素

1.  磁盘的调度算法，是否最优。
2.  PERC 卡的驱动，版本是否比较久，更新个新版本。
3.  系统 OS 的版本。7版本和8版本有很大的区别
4.  磁盘本事的问题或是链路问题。
5.  使用 Live CD 进行测试对比。
