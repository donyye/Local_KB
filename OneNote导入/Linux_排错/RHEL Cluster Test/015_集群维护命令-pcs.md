》资源管理

1）这个命令会重置所有资源的状态和 故障计数

\[root@rh8b \~\]# pcs resource cleanup

Cleaned up all resources on all nodes

Waiting for 2 replies from the controller

\... got reply

\... got reply (done)

\# 如果需要指定资源 "pcs resource cleanup resource_id"。

运行后"Migration summary"与"Faile Resource Actions"这些信息会被清空。

![[RHEL Cluster Test_015_集群维护命令-pcs_003.png]]

 

2）清除集群资源的失败状态

pcs resource failcount show \--full 可以查看资源失败的次数\
从 Red Hat Enterprise Linux 7.5 开始，pcs resource cleanup 命令只会探测显示为失败操作的资源。要探测所有节点上的所有资源，使用命令：pcs resource refresh

 

pcs resource cleanup 和 pcs resource refresh 命令都清除资源的操作历史记录，并重新检测资源的当前状态。pcs resource cleanup 命令仅对集群状态中显示为失败操作的资源进行操作，而 pcs resource refresh 命令则会对资源进行操作，而无论其当前状态如何，慎用。

 

3）查看集群的配置信息

\[root@rh8b \~\]# pcs config 

\...\...

\# 从集群的配置信息里可以看到节点数目、资源（包括VIP）、状态等信息。

4）设置资源超时时间

\# pcs resource op defaults timeout=90s

\# pcs resource op defaults

 

 

5）设置资源默认粘性（防止资源回切）

\# pcs resource defaults resource-stickiness=100

\# pcs resource defaults

![[RHEL Cluster Test_015_集群维护命令-pcs_004.png]]

 

以下命令创建了一个位置约束，以指定资源 nfsgroup 首选节点 node1。

\# pcs constraint location nfsgroup prefers node1.abc.com

 

\# pcs constraint location

Location Constraints:

  Resource: nfsgroup

    Enabled on:

      Node: node1.abc.com (score:INFINITY)

\# 设置之后，服务会优先跑在 node1上，如果它重启，服务会切换到其它节点，但是 node1 起来后，服务还是会回到node1上。就算你设置了 "resource-stickiness=100"也不起作用。

 

6\) 重启资源组命令

\# pcs resource restart \<resource_name\>

7）将资源移出节点

\# pcs resource move \<resource_group\> \<destination_node_name\>

8) 果发现配置的资源没有运行，可以运行下面命令来测试资源配置。

\# pcs resource debug-start \<resource_name\> 

 

 

》二个节点时，忽略节点quorum功能

\[root@rh8a \~\]# pcs property set no-quorum-policy=ignore

![[RHEL Cluster Test_015_集群维护命令-pcs_005.png]]

\# quorum 法定人数

\# pcs property \--all \|grep no-quorum

\# pcs quorum unblock[  \--\> RHEL7 ]使用 pcs cluster quorum unblock

命令用于解除集群的禁止状态，允许集群继续操作，即恢复正常的运行状态。在某些情况下，集群可能由于丧失多数节点的投票权而处于阻塞状态，这可能是由于网络问题或节点失效引起的。使用此命令可以解除这种禁止状态，使集群能够继续正常运行。

\# 使用这个命令时需要特别小心。在运行此命令前，请确定关闭没有在集群中的节点，并确保无法访问共享资源。

》集群配置文件

1）将群集资源配置信息保存在指定文件\
\# pcs cluster cib ra_cfg[                ]

2）创建群集资源并保存在指定文件中（而非保存在运行配置）

\# pcs -f ra_cfg resource create ......

3）显示指定文件的配置信息，检查无误后

\# pcs -f ra_cfg resource show              

4）将指定配置文件加载到运行配置中

\# pcs cluster cib-push ra_cfg
